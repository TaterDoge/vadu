# NSH 架构

> 当前桌面翻译通过 TypeScript 内置 Chat Completions 适配与 NSH `fetch` 访问服务商。第三方插件 VM 与授权桥为目标设计。实现进度见[迁移范围](../nsh-migration.md)。

## 1. 已确定的边界

- 保留用户安装第三方 JS 插件；内置与第三方插件遵循同一业务契约。
- 窗口与其他平台能力通过 NSH API 使用，Profile 校验、配置、凭据与翻译任务在 TypeScript 模块中实现。
- 第三方插件宿主的授权与隔离属于目标设计。
- 第三方 JS 在独立插件 VM 中执行，不装进 UI VM，不要求用户编译 Rust 动态库或 Wasm。
- 插件隔离与加载是 Vadu 要实现的能力，不是 NSH 已提供的翻译插件系统。

## 2. 窗口与运行时

NSH 自有窗口由同一个应用 engine 渲染，共享响应式状态与模块。设置主窗口和通过 `Window.open` 创建的翻译工作台，不等同于 Electron 的两个 renderer 进程。独立嵌入的 view 才可能拥有另一套 engine / VM。

主窗口通过 `src/tray.ts` 使用 `nsh/desktop` 的原生托盘，不新增 Rust 桥接。启动显示设置；关闭主窗口只隐藏，托盘可重新聚焦原窗口或退出应用，隐藏不卸载视图；生命周期配置见 [菜单栏托盘](../../README.md#菜单栏托盘)。

因此，两扇应用窗口可以共用视图状态，不需要互发窗口消息。普通配置统一由 TS 设置模块读取、校验和更新；UI 中的共享状态只是视图快照，不能绕过保存校验。

`App.tsx` 挂载设置主窗口。窗口 TSX 分别位于 `src/windows/settings/SettingsWindow.tsx` 和 `src/windows/translate/TranslateWindow.tsx`。设置窗口使用 shadcn-nsh 的固定 Sidebar 和 NavStack / NavPage。五个一级分类用 `replace` 切换，选中态来自路由栈。SidebarContent 独立滚动。

五个设置分类各自使用 `src/windows/settings/pages/<分类>/` 下的独立 Page 组件，路由配置通过 `render` 统一挂载当前页，不为快捷键页单独分支。`SettingsWindow.tsx` 负责侧栏、路由、滚动容器与内容区的可访问名称，不再渲染公共标题、分类说明或业务未迁移提示。快捷键页通过 NSH keymap 录入全局组合，通过 TS Settings 保存键位和开关或清空键位。局内键帽和开关只读。`src/feature/settings/shortcuts/runtime.ts` 集中声明已实现动作的 ID、作用域与执行函数，由 `setupShortcuts` 统一观察已保存组合：全局作用域使用 NSH GlobalShortcut，窗口作用域通过响应式 `Window.get` / `state` 仅在目标窗口可见且聚焦时使用 NSH keymap。翻译窗组件不再读取快捷键配置或维护绑定；录入期间两类动作均暂停，管理器卸载时统一清理，重挂时可重新绑定仍打开的翻译窗；外观页提供显示模式、强调色与 Nova / Lyra 风格切换；服务商页管理翻译 Profile 与本地存储中的 API Key，通过 TypeScript 请求模块查询模型。通用与备份恢复页为空容器。

两窗口共享 NSH Gallery UI 的语义 token 和组件样式。`nsh-ui.json` 记录构建预设 `theme`，`theme.json` 提供实际配色。`src/feature/settings/appearance/theme.ts` 读取 `settings.appearance`，用 `selectTheme` 应用强调色和字体，用 `setColorScheme` 应用显示模式。组件的尺寸和交互样式来自 `lib/ui/semantics.json`。按钮的键盘焦点沿用预设的 `focusRing()` 样式。设置页输入框使用当前强调色绘制焦点边框。翻译浮窗的原文编辑区与下方工具栏共用 1pt 外边框，默认透明，悬停使用 `border` 色，面板内聚焦时使用 `muted-foreground` 色。文本光标提示编辑位置，工具按钮保留独立的键盘焦点轮廓。输入、弹层、通知和图标使用 registry 组件或其样式工具。

翻译浮窗使用 shadcn-nsh 的 `TitleBar` 拖拽窗口，两个工具按钮沿用 `IconButton`。设置窗口的拖拽区域覆盖可滚动的侧栏，横向 `TitleBar` 无法覆盖这块区域，固定 `Sidebar` 因此透传 `desktop.windowDrag`。快捷键录入使用 `Kbd`，外层 NSH `View` 在失焦时取消录入。服务商列表每行只有一个 Tab 焦点，`buttonLook` 的焦点环包住拖拽手柄、名称和状态。手柄通过原生 responder 拖拽排序，整行提供上移 / 下移辅助操作。列表与详情的滚动区各为焦点环预留 4 点。翻译结果用原生 `Scroll` 和可选文本呈现流式结果。托盘使用 `nsh/desktop` 的 `Tray` 和原生图像。

翻译工作台定位为只通过快捷键唤起，不接入设置主窗口导航。当前 `openTranslateWindow()` 通过 `Window.open` 使用固定 ID `translate` 创建或重用翻译窗口，再聚焦；不设置父窗口。窗口类型与层级约束见[窗口与导航范围](../nsh-migration.md#2-窗口与导航范围)，不把翻译窗聚焦等同于激活整个应用。未固定的浮窗失焦时调用 `hide()` 并保留输入。固定后使用 `aboveDock` 层级，失焦时保持可见。设置窗口挂载时，仅为开启且有键位的全局项注册快捷键。隐藏设置窗口时保持注册，关闭开关或清空键位时释放组合，录入时暂停，卸载时注销并忽略过期回调。窗口切换与注册生命周期已有 headless 测试。macOS 原生测试宿主已用本地服务确认浮窗隐藏和关闭时断开上游连接。跨应用热键与其他桌面后端的原生行为仍需验证。

## 3. 职责与调用方向

模型查询和健康检测由 `src/api/models.ts` 发起，流式翻译由 `src/api/translation.ts` 发起。它们共用 `chat-completions.ts` 中的 Profile 和凭据读取逻辑，并用 `request.ts` 或 `stream.ts` 读取 JSON 或 SSE。底层统一限制重定向、期限和响应体积。`src/api/translation-task.ts` 按 `requestId` 分发事件并处理取消。下图描述后续的独立 JS 插件路径。

```text
设置中心 / 翻译工作台（NSH TSX，同一应用 engine）
    ├── 配置和密钥 → TS Settings → NSH Storage
    ├── 内置请求与任务 → TypeScript → NSH fetch
    ▼
插件宿主（目标设计）
    └── 受控 HTTP、凭据、日志与插件生命周期
             ▲
             │ 调用上下文 / 结果
             ▼
独立 JS 插件 VM（按插件隔离，不共享 UI VM）
    └── 翻译 / OCR / TTS 的一次协议调用
             │ runtime.fetch，经宿主权限检查
             ▼
          外部服务
```

| 层            | 负责                                  | 不负责                                                |
| ------------- | ------------------------------------- | ----------------------------------------------------- |
| TSX 视图      | 输入、展示、页面草稿、按请求更新状态  | 厂商网络请求、直接读取 API Key 或写配置文件           |
| TS 设置模块   | 配置与凭据的校验、串行存取            | 插件执行与授权                                        |
| TS 请求与任务 | 内置请求、SSE 解析、事件与取消        | 持久化凭据、第三方插件执行                            |
| 插件宿主      | 未来插件的隔离、授权和生命周期        | 厂商请求、提示词与响应解析                            |
| 插件          | 一次翻译 / OCR / TTS 调用与协议适配   | 自行读写配置、跨 Profile 取密钥、窗口、重试与缓存策略 |
| 平台设施      | 窗口、快捷键、NSH Storage、文件选择等 | 复用 Electron API 或绕过业务校验                      |

不预建缓存、自动重试、语言检测、术语表或万能能力调用框架。需要这些业务时，再在核心中设计；不由每个插件自行实现。

## 4. 业务调用与平台 API

TSX 视图直接调用同一 engine 中的 TypeScript 模块。网络和存储异步执行。翻译任务在受理时登记回调，按 `requestId` 处理并发、取消和过期结果。输入、事件、取消与错误语义见[平台 API](./native-api.md)。

## 5. 插件宿主与信任边界

独立插件 VM 由宿主管理，只注入当前调用需要的能力。UI 模块、原生模块注册表和系统模块不得直接暴露给插件。

- 网络只能通过宿主受控桥；凭据只向本次调用所属 Profile 提供。
- 设置内存上限、执行期限与中断机制；不能依赖插件主动检查取消来处理死循环。
- 插件加载失败、崩溃或超限，应终止所属任务并标记插件不可用，不能阻塞设置窗口启动。
- 禁用、卸载与应用退出要终止相关任务并释放 VM。
- 安装前展示来源与权限，用户确认后才启用；权限扩大需再次确认。

这是待实现的隔离目标，不是现有安全保证。QuickJS VM 隔离也不等于 OS 进程沙箱；原生桥和运行时漏洞仍影响宿主安全。未经隔离验证，不应对外开放第三方安装入口。

NSH 发布模式禁用 UI 中的 `eval` / `new Function` 等动态执行。不能用 UI 动态求值装插件，也不能通过关闭发布加固来绕过。独立插件 VM 的模块加载器须单独实现并验证发布构建。NSH 的签名 `.nsh` 应用包不等同于 Vadu 的业务插件包。

插件格式、调用上下文、权限与 AI 协议适配见[插件规范](./plugin-spec.md)。

## 6. 数据与保密

| 概念     | 唯一职责                                                         |
| -------- | ---------------------------------------------------------------- |
| Plugin   | 一种能力的实现、配置 schema 与权限声明                           |
| Profile  | 用户配置实例，绑定一个插件；包含端点、模型等非密钥配置与启停状态 |
| Preset   | 创建 Profile 的只读模板；更新模板不得覆盖用户已有实例            |
| Settings | 应用级偏好，不混入某个服务商配置                                 |
| Secrets  | 按 Profile 隔离的 NSH Storage 键，不混入普通配置                 |

核心解析明确选中的 Profile，再决定插件；不得暗取第一个 AI 配置。Profile 关闭后保留数据，但不再接受新任务。不存在或插件不可用的引用要报错，不能静默换厂商。

`src/feature/settings/index.ts` 提供统一调用入口，外观、快捷键与服务商模块分别管理字段、校验和修改命令。`src/feature/settings/store.ts` 在同一应用 engine 内串行读取最新文档并修改单项，通过 NSH Storage 的 `vadu.config` 整包保存，底层后台写入并原子替换。此队列不提供跨进程事务。当前保存外观、快捷键与服务商 Profile。保存服务商时，普通配置先写入 `vadu.config`，本次输入的密钥再写入独立键 `vadu.secret.<profileId>`。NSH 0.6.0 的写盘回执、删除顺序和整包备份恢复方案见[配置存储设计](./storage.md)。

设置页聚焦时将当前服务商的已保存密钥载入密码输入框，默认遮蔽，点击眼睛可查看。窗口失焦时清除已载入的密钥，重新聚焦时恢复遮蔽显示。新输入的密钥只短暂存在于输入与提交路径，提交后清空。密钥是 NSH Storage 中的明文；读取失败时不覆盖原数据。凭据和授权的细节见[平台 API](./native-api.md#6-输入凭据与授权)。

日志默认不记录密钥、Authorization 头、翻译原文、译文或上游响应正文。确需识别密钥时最多前 4 后 4 位，短密钥全部遮蔽；正常诊断只记 `requestId`、插件 ID、耗时与安全错误码。

卸载插件不得静默删除关联 Profile 或密钥；删除配置、凭据或恢复覆盖必须单独确认。整包备份格式与确认后恢复流程已有设计但尚未实现；Electron 数据导入另行确认，不承诺旧格式兼容，也不继承旧版明文密钥导出行为。

## 7. 框架能力与待验证项

| 已核对的 NSH 机制                 | Vadu 仍需验证 / 实现                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------- |
| 应用自有窗口共享 engine           | 局内按键、置顶层级和关窗取消的跨平台原生验证                                       |
| TS `fetch` 有流与 AbortController | 内置请求已接入。代理、Cookie 与断连语义依平台网络栈，见[平台 API](./native-api.md) |
| 能力声明可限制 NSH 提供的服务     | 每插件权限、URL 与重定向校验                                                       |
| NSH 使用 QuickJS 与有限标准模块   | 独立插件 VM、模块加载、资源配额与 npm 包兼容                                       |

当前 `nsh.json` 没有声明 capabilities，不能称应用已处于最小权限沙箱。实现时应按实际使用收紧；应用级声明不能替代每插件、每 Profile 的授权。

### 原生验收步骤

以下步骤在目标桌面的独立测试账户执行，使用测试 Profile 和本地假服务。仅观察窗口状态、请求次数、连接关闭和重启后的界面。

| 环境                                      | 操作与通过条件                                                                                                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 装有 Vadu 的 macOS、Windows 或 Linux 桌面 | 切到外观页，关闭设置 → 托盘打开设置，确认原分类与窗口恢复。从其他应用触发全局热键两次，只出现一个翻译窗。固定后切窗应保持可见，取消固定再切窗应隐藏。最后从托盘退出。 |
| 可让出前台焦点的 macOS 测试桌面           | 运行 `nsh test "tests/Shortcuts.test.tsx" --target macos --foreground`，核对按键录入、取消与重置。                                                                    |
| 目标平台发布包与可延迟发送 SSE 的本地服务 | 确认本地地址后，测试模型列表和健康检测。让假服务发送首段译文并保持连接，分别用取消按钮、隐藏和关闭结束翻译，服务端应收到断连。重开后只显示本次请求的结果。            |
| 目标平台发布包与独立测试数据目录          | 保存测试服务商、模型、快捷键和测试密钥，正常退出再启动。检查设置恢复，查看凭据需点击显示，改填其他地址后该凭据不可用。                                                |
