# NSH 插件规范

> 设计草案，尚无插件加载器或已发布的 NSH 插件 SDK。保留用户安装第三方 JS 插件；本规范不代表旧 Electron 插件可以直接运行。

## 1. 插件的职责

一个插件只提供一种能力：`translator`、`ocr` 或 `tts`。同一插件可以供多个 Profile 使用；每次调用独立，不自行处理配置持久化、自动重试、缓存、语言检测或窗口 UI。

当前内置 OpenAI 兼容翻译适配位于 `src/plugins/openai.rs`，由 Rust 核心调用。它实现模型列表、当前模型的 Chat Completions 对话检测与 Chat Completions SSE。后续第三方 JS 插件通过独立 VM 和本规范的能力契约接入。厂商请求和协议解析留在能力适配内。

## 2. 分发与版本

插件包含 `manifest.json` 与一个自包含 JS ESM bundle。插件作者在发布前打包依赖；宿主不安装 npm 包、不执行安装脚本、不提供 Node 运行时。

```text
plugin/
├── manifest.json
└── index.mjs
```

清单关键字段草案：

```json
{
  "id": "example.translator",
  "name": "Example Translator",
  "version": "0.1.0",
  "apiVersion": 3,
  "kind": "translator",
  "main": "index.mjs",
  "permissions": ["net:*"],
  "configSchema": {
    "baseURL": { "type": "string", "label": "接口地址", "required": true },
    "model": { "type": "string", "label": "模型", "required": true },
    "apiKey": { "type": "secret", "label": "API Key", "required": true }
  }
}
```

- `id` 是稳定插件身份，不是目录路径；用户插件不得覆盖内置插件 ID。
- `main` 是包内入口，不能为绝对路径、越界路径或指向包外的链接。bundle 不依赖运行时外部模块解析或动态下载代码。
- `apiVersion: 3` 是本次 NSH 协议草案版本，用来明确区别于 Electron v2；不是 NSH 框架版本，也不是已经发布的兼容承诺。
- 宿主只接受自己明确支持的协议版本；不加 Electron v2 兼容层。旧插件需要重新打包、适配新 runtime 并验证。
- 破坏字段、调用或权限语义时升协议版本；兼容的可选字段不机械升版。新增权限必须先在本规范定义，并要求用户确认。

安装载体与完整 schema 在最小插件验证通过后定版。文件清单、大小、ID、版本、入口、kind 和权限均由宿主校验；如果采用归档，必须拒绝目录穿越、越界链接和解压超限。安装过程不能执行插件提供的脚本。

## 3. 创建与调用

bundle 导出 `createPlugin()`，返回与 manifest kind 一致的实现。工厂不绑定某个 Profile 的凭据；调用时由宿主逐次传入上下文。

| kind       | 方法语义                       | 请求内容                 | 结果                                               |
| ---------- | ------------------------------ | ------------------------ | -------------------------------------------------- |
| translator | `translate(request, runtime)`  | 原文、源语言、目标语言   | `AsyncIterable<string>`，每段是新增译文            |
| ocr        | `recognize(request, runtime)`  | 图片字节、媒体类型       | `Promise<{ text: string }>`                        |
| tts        | `synthesize(request, runtime)` | 文本；声音等来自本次配置 | `Promise<{ audio: Uint8Array; mimeType: string }>` |

翻译插件只产出文本片段，不发送 UI 的 done/error 事件；核心负责聚合最终文本、错误归一与唯一终态。OCR / TTS 返回一次结果，不要求伪造文本流。

翻译插件可选提供 `listModels(runtime): Promise<ModelInfo[]>`，其中 `ModelInfo` 为 `{ id: string; label?: string }`。没有该方法时允许用户手填模型，不为获取列表阻塞翻译。列表请求同样受授权、取消、期限与输出数量限制。健康检测由宿主通过独立对话请求完成，不要求第三方插件提供同名方法。

方法与二进制类型是目标语义，具体 JS SDK 类型需随桥接验证冻结；不能直接复用浏览器对象或旧 Node 类型作为实现保证。

### 每次调用的 runtime

| 成员                                      | 约束                                                                |
| ----------------------------------------- | ------------------------------------------------------------------- |
| `requestId`                               | 宿主提供的当前调用 ID                                               |
| `signal`                                  | 本次调用的取消信号；超时、禁用、卸载和关窗都能终止上游              |
| `config`                                  | 核心校验后的非密钥配置快照；插件不得反向修改 Profile                |
| `fetch`                                   | 宿主提供的受控 HTTP 桥，必须支持翻译流与取消                        |
| `secrets.get(name)` / `secrets.has(name)` | 只绑定当前 Profile、schema 已声明的凭据；不得枚举或访问其他凭据桶   |
| `log`                                     | 带插件 ID 和 requestId 的受控日志，宿主脱敏，不提供任意系统日志接口 |

插件不得将 runtime、密钥或可变配置存入模块全局后供其他调用复用；并发调用不能串 Profile、文本、signal 或连接。上下文必须逐次绑定，不能通过更换全局“当前 Profile”实现。

不同插件使用独立 VM。若同一插件复用 VM，逐次上下文只是调用契约，不构成对该插件内部恶意代码的跨 Profile 强隔离。插件能接触授权给它的凭据，因此必须信任其来源；宿主脱敏和 origin 白名单不能保证恶意插件无法记忆、编码或向获准端点泄露这些数据。

## 4. 独立 VM 与宿主桥

插件不能访问 UI VM、`nsh` / `vadu/native` 注册表、文件系统、进程启动、环境变量、宿主 NSH Storage 中的 API Key、任意 native FFI 或 Node `require`。静态依赖应已打进 bundle，不能从宿主环境捡到额外权限。

插件所需 Promise、异步迭代、Uint8Array、定时 / 取消和 HTTP 流对象，要由独立 VM 与宿主桥明确提供。不能因为 NSH UI 有某个全局对象，就宣称插件 VM 已兼容。

- 默认不提供不受控的全局网络 API；若为 SDK 兼容提供 `globalThis.fetch`，必须走与 `runtime.fetch` 相同的授权、期限和取消检查。
- 不注入文件 / 系统模块来“让 npm SDK 先跑起来”。兼容失败时调整依赖或协议实现，不能放开宿主权限。
- 不在 UI 里使用 `eval` / `new Function` 加载 bundle；独立 VM 由 Rust 的受控模块加载器执行。
- VM 设置可测试的内存、执行时间和中断限制；具体配额由最小验证确定，不能把 NSH UI 的默认值当插件配额。
- 宿主必须限制响应、输出与回调队列体积，处理快速产出、死循环、崩溃和取消后继续输出。

独立 VM 是隔离目标，不等于 OS 沙箱；独立运行时、桥接权限与发布构建均通过验证后，才能开放第三方安装。

## 5. 网络权限

插件声明与 Profile 端点授权取交集，不能只检查其中一层。

| 声明                          | 语义                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------- |
| `net:https://api.example.com` | 精确 origin，默认 HTTPS 端口；不包含任意子域名或其他端口                         |
| `net:*`                       | 支持用户自定义端点；仍只能访问当前 Profile 已确认的有限 origin，不是任意网络权限 |

- 使用 URL 解析器规范化协议、主机和端口，按 origin 比较，禁止字符串前缀匹配。
- 只接受 HTTP / HTTPS；拒绝 URL 用户信息、非法地址及其他协议。明文 HTTP 的风险必须在授权时说明，不能由 HTTPS 静默降级。
- 自定义端点保存前展示实际 origin，由用户确认；`allowedOrigins` 由宿主保存，插件或 UI 不能直接写入白名单。
- 重定向默认不自动跟随，避免绕过检查或把认证头带到别处。若以后允许，须先定义并测试每一跳的授权与凭据规则。
- 本地服务也要绑定用户明确选择的 origin；`localhost`、私网或不同端口不自动获得通行。
- 实际请求必须绑定本次 signal；取消、超时和 VM 销毁都要关闭连接与流 reader。

NSH 应用 capabilities 不能替代这里的每插件检查。Rust 原生代码拥有进程权限，受控桥必须自己守住边界。

## 6. 配置、模板与凭据

配置 schema 是纯数据，宿主渲染表单；不执行插件提供的 UI、校验脚本或任意组件。首轮只定义实际需要的字段类型与约束，不照搬历史预留能力。

- 字段至少区分普通值和 `secret`；宿主校验必填、类型与声明的取值限制，拒绝不支持的 schema。
- 普通配置剔除 secret 与未声明字段，插件只能得到通过校验的快照。
- secret 单独写入按 Profile 隔离的安全存储，不进入 manifest、Preset、Profile.config、错误或日志。
- 宿主设置页用密码输入框编辑密钥，用户可主动切换明文显示。编辑留空保留原凭据，删除 Profile 时由宿主确认后清除。
- Preset 只描述创建 Profile 的默认配置，不含密钥、不代表运行实例；更新不覆盖用户已有配置。
- 普通配置与凭据的保存、失败恢复和删除确认由宿主完成，插件不得自行持久化。

任意 headers / extra、模型专属高级参数等历史扩展，不因旧文档存在就成为新协议既定接口；需要迁移时先明确校验与敏感字段边界。

## 7. AI 服务商组织

保留一个 AI 翻译插件、按协议适配的组织方式：

```text
AI 翻译插件
├── openai 协议适配
├── anthropic 协议适配
└── gemini 协议适配
    ↑
Profile 选择协议、baseURL、model；Preset 提供创建默认值
```

这些是需要迁移的协议方向，不表示当前已有三个可运行适配器。新增兼容厂商优先添加 Preset，不复制一份插件、不在核心或 UI 按域名写厂商分支；协议确有差异时在插件内部适配。

- 用户自己选择端点、模型与密钥；不内置共享密钥，不静默切换厂商或模型。
- 提示词只要求译文，保留原文 Markdown 与占位符；待译文本作为用户内容，不拼成系统指令。
- 不把旧模型清单、温度、token 上限和超时常数当作当前真相；宿主期限与协议必需参数在接入时验证。
- 旧 `ai` / `@ai-sdk/*` 是 Node / Web 生态依赖，不保证可在本插件 VM 运行。先验证打包、流、取消与所需全局 API，再决定复用 SDK 还是写最小协议适配。
- SSE / 流解析要处理跨 chunk、UTF-8 边界、异常 EOF 与错误响应；不能把一段 TCP 数据直接当完整事件。

## 8. 生命周期、错误与发布前检查

宿主先校验 manifest 与授权，再创建 VM、加载入口并检查工厂和 kind。初始化失败只影响该插件；失败状态和安全原因可见，不阻塞应用启动。

用户安装入口由宿主选择文件 / 目录，展示来源与权限再确认启用。同 ID 更新需用户明确确认，不静默覆盖；权限扩大需重新授权。禁用 / 卸载先终止相关任务并释放 VM，不能静默删除 Profile 和密钥。

错误码统一引用[原生 API 错误表](./native-api.md#3-结构化业务错误)。插件可报告业务错误，宿主校验并重新脱敏、决定 retryable；未知异常归一，不将原始上游正文回传。取消与唯一终态由核心保证。

开放第三方插件前至少验证：

- 清单非法、协议不匹配、重复 ID、越界入口、初始化异常不会执行越权代码或影响应用启动。
- 两个 Profile 并发不串凭据；普通配置、UI 快照、日志与错误没有已知敏感值。
- 未授权 origin、前缀伪装、端口变化、重定向和全局 fetch 均不能绕过受控桥。
- 翻译真实逐块到达；取消关闭上游，插件忽略 signal、死循环或超限时宿主仍能终止。
- SDK 所需全局 API 有明确实现；没有意外的文件、进程、UI 或原生模块访问。
- 发布模式下完成插件加载与完整调用，不依赖开发模式动态求值。

当前不建设插件市场、自动下载 / 更新、插件 UI、运行时依赖安装或跨插件调用。
