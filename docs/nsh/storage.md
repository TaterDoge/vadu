# NSH 配置存储与备份恢复

> 当前实现：快捷键录入、校验、保存、重新读取与单项重置。后续设计：其余偏好接入、整包导出与确认后恢复。备份页仍为空，没有导入 / 导出 API。

## 1. 一条写入路径

```text
ShortcutsPage 的输入 / 视图快照
    → src/settings.ts 的 Settings
    → TS 串行读取最新文档、运行时校验、修改单项
    → NSH Storage["vadu.config"]（完整 JSON）
    → NSH 后台原子替换 storage.json
```

选 NSH 自带存储，不引入数据库、前端 localStorage 封装、通用 KV API 或新的文件线程。所有普通配置共用一个带版本的业务文档；后续备份复用该文档，不需要分别收集各页面的 signal。

- **TS 设置模块是唯一业务入口**：默认值、动作 ID、运行时校验、规范化、录入键表与序列化集中在 `src/settings.ts`，类型只在 TS 定义，不再维护 Rust 包装。
- **UI 只提交意图**：如修改某个快捷键，不把旧的整包配置传回保存。每次操作读取最新值后更新单项。
- **整段读改写串行**：Storage 只保证单次调用有序，设置模块用 Promise 队列协调同一应用 engine 内的更新，避免两个异步读改写丢失修改；失败不阻塞后续操作。读取等待此前排队的写入。此队列不提供跨进程事务，不自动广播其他页面的视图快照。
- **一包提交**：校验和编码全部成功后，只调用一次 `Storage.setItem`；业务校验失败或存储配额不足，不修改原值。成功读取或保存后更新 `Settings.current()` 响应式快照，供全局与局内快捷键观察；失败不发布新值。
- **不分散读写**：后续普通配置仍由对应业务入口提交，不在页面直接调用 Storage。暂不建立通用仓储接口、订阅层或迁移框架。

使用 `nsh` 导出的异步 `Storage.getItem` / `Storage.setItem`，不自建配置文件路径或磁盘 I/O。`JSON.parse` 的结果作为不可信输入逐层校验，不能靠类型断言跳过。NSH 负责本地加载与后台写盘；TS 迁移保留 `vadu.config`、`schemaVersion: 1` 和现有字段，无需迁移或删除已存数据。

## 2. 当前数据格式

NSH 的外层文件是 KV 字典。业务只拥有 `vadu.config` 这个键，其字符串值为：

```json
{
  "schemaVersion": 1,
  "settings": {
    "shortcuts": [
      { "id": "toggle-translate", "keystroke": "mod+shift+m" },
      { "id": "open-settings", "keystroke": "mod+," },
      { "id": "pin-translate", "keystroke": "mod+p" }
    ]
  }
}
```

- `schemaVersion` 管整个配置文档，不是应用版本或插件 `apiVersion`。
- 动作 ID 稳定，组合键存 NSH 语法，不存 `⌘` 等显示文本。`mod` 在 Apple 平台代表 Command，其余平台代表 Ctrl；保存时规范化修饰键顺序。
- 只有键不存在才使用 TS 默认值，读取不会自动写入。不是每次启动都覆盖默认配置。
- 当前必须恰好包含这三个动作，且各出现一次；未知字段、非法键、重复动作或重复组合均拒绝。
- JSON 损坏、版本不支持时，页面提示并禁用编辑，不静默退回默认值覆盖原文档。保留未知字段的“尽力恢复”也不做。

### 存放位置与承诺

NSH 0.6.0 使用应用 ID 作为数据目录：

| 平台 | 默认位置 |
| --- | --- |
| macOS | `~/Library/Application Support/<app-id>/storage.json` |
| Windows | `%APPDATA%/<app-id>/storage.json` |
| Linux | `$XDG_DATA_HOME/<app-id>/storage.json`，未设时使用 `~/.local/share/` |

当前 `nsh.json` 的 ID 为 `com.example.vadu`。正式发布前确定稳定 ID；更改 ID 会改变目录，本实现不会自动迁移旧目录。

NSH Storage 上限为所有 KV 合计 **5 MiB**。`setItem` 接受内存更新后完成 Promise，后台合并写盘并原子替换文件；正常退出会等待后台写入。**调用成功不等于已 fsync**：磁盘权限、空间或底层读写错误没有完整的业务回执，不能向 UI 承诺“已可靠写入磁盘”。Vadu 能识别的是业务键中的坏 JSON；底层整个 `storage.json` 读失败可能由 NSH 降级为内存存储，当前业务入口不能可靠识别。

因此本切片适用于小型偏好，不用于密钥、大文件、任务结果或需要事务保障的数据。不能用直接复制该文件实现备份。正式接入恢复前，必须补齐可报告落盘失败的持久提交能力：优先使用届时 NSH 的确认机制；若仍不支持，再在设置模块后接入可确认的原生存储能力，不改 UI 的业务入口。

## 3. 快捷键录入契约

- 键帽组悬停、键盘聚焦与录入时以背景色提示，不显示边框；点击或键盘激活后进入录入，显示“请按下快捷键…”，保留可访问名称。
- 使用 NSH `keymap.bind` 临时捕获支持的组合：字母、数字、常见标点、导航键和 F1–F24。不是浏览器 `keydown`，不把键盘业务放进通用 Kbd 组件。
- 合法值需要 Command / Ctrl / Alt 中至少一个修饰键，或 F1–F24；裸字母和仅 Shift 的普通键不保存。
- TS 设置模块借助 `keymap.label` 校验 NSH 语法，规范化别名后检查组合重复，并按 NSH 0.6.0 的平台规则排除系统保留键；升级 SDK 时同步核对规则。保留键不加入临时表，仍可能执行系统行为；不能把此校验当作所有 OS / 其他应用的快捷键冲突检测。
- Esc、Tab、Shift+Tab、失焦、切页、应用退到后台时退出并清理临时表。Tab 继续正常移焦；新组合提交前取消不写入，已提交的配置更新不因退出录入回滚。
- 校验或配额失败保留旧配置，留在录入状态以便重试；成功才更新键帽。原有全局项的重置按钮恢复该项默认值，仍检查冲突。
- **保存不等于注册成功**：“唤起翻译浮窗”沿用已保存的 `toggle-translate` ID，在启动时自动注册，保存或重置后换绑；录入任一项时暂停，取消后恢复。页面显示正在注册 / 已启用 / 失败状态，占用或不支持时保留已保存配置、不静默换键。坏配置不注册默认键。打开设置与固定窗口局内动作使用已保存组合，仅翻译窗聚焦时绑定、保存后立即换绑，不新增启用字段；页面显示启用状态。固定状态随翻译窗口关闭而清除。
- 开发宿主的 `mod+r` 是热重载键，不经过普通业务捕获；该键的实际录入行为需发布宿主验证。

## 4. 后续配置如何接入

当前代码只落地 `settings.shortcuts`，不添加空的预留字段。真正实现业务时，在文档同一层逐步加入对应数据：

| 数据 | 持久化位置 / 整包备份策略 |
| --- | --- |
| 应用偏好，如外观与快捷键 | `settings`；由各领域命令更新，统一导出 |
| 用户服务配置 Profile | 文档内独立 `profiles`；仅非密钥字段，严格遵循插件 schema |
| 用户修改的 Preset | 单独集合；内置只读模板随版本提供，不复制到用户配置 |
| 已安装插件元数据 | 稳定 ID、版本、来源与选择；不夹带插件代码、任意路径或可直接生效的权限授权 |
| Secrets | 独立系统安全存储；绝不进入本 JSON 或普通备份 |
| 原文 / 译文、缓存、日志、UI 草稿、临时录入状态 | 不属于配置文档，不随配置导出 |

外观目前仍为运行期 signal，本次没有顺便迁移。Profile 和插件也尚未实现。新增配置字段时升级 `schemaVersion`，为实际旧版本增加明确的纯数据迁移和测试；不预写空迁移链。迁移先在内存完成并完整校验，验证前不得覆盖源文档；新版本配置被旧应用打开时拒绝写入。

带凭据引用的 Profile 恢复后，没有本机匹配凭据就标记“需重新输入”，不读取 / 导出旧密钥，也不能暗用其他 Profile 的凭据。恢复不能自动删除当前安全存储中的项目。URL 等自由文本也可能夹带敏感内容；未来 Profile 保存与导出必须按 schema 拒绝凭据字段和带认证信息的 URL，不能声称任意用户文本都天然无密。

## 5. 整包导出 / 导入设计（尚未实现）

### 备份格式

导出设置模块校验过的完整业务文档，用薄 envelope 标记来源。建议 `.vadu.json`，不是 NSH KV 文件：

```json
{
  "format": "vadu-backup",
  "formatVersion": 1,
  "createdAt": "2026-01-01T00:00:00Z",
  "appVersion": "<exporting-app-version>",
  "config": {
    "schemaVersion": 1,
    "settings": {
      "shortcuts": [
        { "id": "toggle-translate", "keystroke": "mod+shift+m" },
        { "id": "open-settings", "keystroke": "mod+," },
        { "id": "pin-translate", "keystroke": "mod+p" }
      ]
    }
  }
}
```

`formatVersion` 只管理备份外壳；`config.schemaVersion` 管配置迁移；`appVersion` 只供诊断，不能代替 schema 判断。用户文件视为不可信输入，不能把整个对象直接塞入 NSH Storage。

导出流程：宿主授权选择目标文件 → 设置模块获取并校验最新快照 → 从明确允许的配置类型编码 → 宿主写临时文件并确认原子替换成功。用户取消不写文件；不接受 UI 任意路径，不把整个 Storage、系统凭据或日志打包。尚未接入敏感文件能力，授权与文件写入测试随该功能一起实现。

### 恢复流程

1. **选择、限额读取**：宿主文件选择，先限制备份文件大小，再解析 `format`、版本、字段与引用；上限根据届时存储配额制定，先拒绝超限输入。
2. **迁移、预检**：在内存迁移到当前 schema，校验全部领域与跨对象引用。按当前平台检查快捷键；冲突、保留键或插件 schema 不可用时返回问题，不部分恢复、不静默更改。
3. **展示差异并确认**：显示将替换的配置类别 / 数量、需补密钥、缺失插件与快捷键问题。第一版只做整包替换，不自动合并或猜测 ID；明确提示会覆盖当前普通配置。
4. **保留恢复前快照**：用户确认后保存当前有效配置的可恢复副本，确认写成功再继续；失败就中止。当前配置损坏则中止自动恢复，另行确认人工保留与处理，不能静默丢弃。恢复前快照同样不含 Secrets。
5. **一次持久提交**：对确认时的当前版本重新检查；确认期间配置改变则重新预览，不能覆盖较新的修改。整包校验通过后一次替换，并等待可靠落盘回执；失败保留原值，不提前宣布恢复成功。
6. **提交后生效**：刷新相关 UI 与实际业务绑定；插件缺失的 Profile 保持不可用、权限重新确认。导入文件绝不能自动安装执行插件或扩大权限。

此流程需要新增有类型的备份业务 API，但当前不声明虚构的生成签名。不把 Storage 调用当作数据库事务，也不承诺“文件 + Keychain + 插件安装”具备跨系统原子性。

## 6. 验证边界

当前 TS 测试覆盖配置往返、非法值 / 保留键 / 别名冲突 / 未知字段 / 未知版本、并发读改写及失败后队列恢复、临时键表可绑定与唯一性，以及页面录入、冲突重试、取消 / 切页 / 生命周期、存储快照重开读取、单项重置、配额失败和 macOS / Windows / Linux 模拟平台语义。

macOS 原生前台宿主已验证 TS 录入、快照重开与重置，以及全局组合被占用时的失败提示和换键后系统接纳注册。原生录入测试需要 `--foreground`；默认后台运行会按生命周期规则取消录入。`tests/GlobalShortcuts.test.tsx` 以替身驱动系统回调，覆盖重复唤起、失焦隐藏与草稿恢复、最小化恢复、关闭重开、主窗口隐藏、换绑、录入暂停、注册失败及过期回调清理。

测试注入的 `storage` 是隔离的引擎快照，不能证明真实磁盘断电恢复、跨应用的 OS 全局按键触发或 Windows / Linux 原生键盘事件。备份落地还需专门覆盖不可信文件、版本迁移、取消与覆盖确认、并发变更、磁盘满 / 无权限、原子替换失败、恢复前副本和发布构建。默认不兼容 Electron 旧备份；需要时另行确认格式和迁移授权。
